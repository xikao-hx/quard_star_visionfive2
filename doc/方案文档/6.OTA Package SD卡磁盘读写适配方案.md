# OTA Package SD 卡磁盘读写适配方案

## 1. 已确认目标

OTA 对 VisionFive 2 的 SD A/B 分区采用两种写入语义：

| OTA 逻辑分区 | 默认设备 | payload | 写入方式 |
| --- | --- | --- | --- |
| `boot_a` | `/dev/mmcblk1p3` | `work/target/amp/starfive-visionfive2-vfat.part` | 从 offset 0 原始写 FAT 镜像 |
| `rootfs_a` | `/dev/mmcblk1p4` | `work/target/amp/rootfs.ext4` | 从 offset 0 原始写块设备 |
| `boot_b` | `/dev/mmcblk1p5` | `work/target/amp/starfive-visionfive2-vfat.part` | 从 offset 0 原始写 FAT 镜像 |
| `rootfs_b` | `/dev/mmcblk1p6` | `work/target/amp/rootfs.ext4` | 从 offset 0 原始写块设备 |

`boot_a/b` payload 是完整 FAT 文件系统镜像，其中包含 `starfiveu.fit`
和 `vf2_uEnv.txt`。boot 与 `rootfs_a/b` 都从分区 offset 0 原始写入、
`fsync()` 并回读比较。`p4` 和 `p6` 均为 2 GiB，可容纳当前 500 MiB rootfs。

## 2. writer 设计

writer 集中维护四个逻辑分区的默认设备和环境变量覆盖：

- `BH_OTA_BOOT_A_DEV`
- `BH_OTA_ROOTFS_A_DEV`
- `BH_OTA_BOOT_B_DEV`
- `BH_OTA_ROOTFS_B_DEV`

默认目标只指向 `mmcblk1p3` 至 `mmcblk1p6`，不操作整盘 `/dev/mmcblk1`。

boot 和 rootfs 使用同一个块写入入口。环境变量指向普通文件时，
该文件视为 host 测试目标，直接写入并回读，不需要 root 权限。

只有 `rootfs_*` 允许 payload 裁掉镜像尾部连续零，`partition_size`
记录原镜像长度；boot FAT 镜像不裁剪，`partition_size` 等于 `size`。

## 3. OTA 包内容和顺序

在线 A/B 包每个 bank 包含四个启动必需 payload：

1. `fw_payload_<bank>`
2. `boot_<bank>`（源文件为 `starfive-visionfive2-vfat.part`）
3. `rootfs_<bank>`
4. `spl_<bank>`

stage1 更新 inactive bank，stage2 在新 bank 启动后更新另一 bank。SPL
排在同 stage 最后，避免先改 BootROM 入口再更新后续镜像。既有
签名、版本、bank 判断、recovery 状态机和断点计数不改。

`gpt.img` 和 `recovery.img` 暂不进入在线 OTA manifest：前者会改变 NOR
分区解释，后者就是 OTA 运行状态。本次不创建 `factory/`；二者
仍由 tools 命令生成，供现有人工刷写流程使用。

## 4. 统一发布产物目录

各组件保留原有 `work/amp` 和 Buildroot 目录作为构建中间输出。
`publish_amp_images` 把 AMP 镜像发布到 `work/target/amp`：

- `u-boot-amp-spl.bin.normal.out`
- `visionfive2_fw_payload_amp.img`
- `image.fit`
- `starfive-visionfive2-vfat.part`
- `rootfs.ext4`

OTA 打包的自动模式从 `work/target/amp` 读取 SPL、fw_payload、FAT boot
分区镜像和 rootfs；单独发布的 `image.fit` 保留用于调试和人工部署。
`publish_amp_images` 不生成或发布 `sdcard_amp.img`；需要 SD 卡整盘镜像时
单独执行 `make amp_img`，产物保留在 `work/`。
`gpt.img`、`recovery.img`、`gpt-layout.txt` 和 `nor-layout.txt` 统一在
`work/target/amp` 生成，但不进入在线 OTA manifest；镜像供实机首次烧写或
人工恢复使用，TXT 文件用于检查对应的 GPT 和 NOR 分区布局。
顶层 `./build.sh package` 固定启用该模式，不从原中间目录取镜像。

## 5. 统一构建入口

根目录 `build.sh` 通过第一个参数选择流程：

- `sdk build normal`：构建普通镜像并发布到 `work/target/normal`；
- `sdk build amp`：构建 AMP 镜像并发布到 `work/target/amp`；
- `sdk build all`：依次发布普通和 AMP 镜像，也是默认模式；
- `bsp`：调用 `bsp/ipi_mailbox/build.sh`；
- `app`：调用 `app/build.sh`；
- `ota`：按依赖顺序构建 OTA info/package/client；
- `tools`：调用 `tools/image/build.sh` 生成 GPT 或 recovery 镜像；
- `keygen`：调用 `tools/script/build.sh` 生成 RSA-2048 OTA 密钥对；
- `package`：调用 `tools/script/build.sh` 从 `work/target/amp` 构建 OTA 包；
- `all`：串联 SDK、BSP、app 和 OTA 组件构建。

顶层入口只负责调度，不复制各子项目内部构建逻辑。

默认私钥位于宿主机 `keys/ota_private.pem`，权限为 `0600`，并由
`.gitignore` 排除；私钥不复制进设备根文件系统。对应公钥生成到同目录，
同时安装为 `nfs_rootfs/etc/ota/keys/ota_public.pem`。OTA 包默认生成到
`nfs_rootfs/ota_package`。执行 `package` 时如果私钥不存在，会先生成密钥对；
已有私钥只做格式校验，不会覆盖。

## 6. 实施与安全边界

1. 实现 boot FIT 文件更新和 rootfs SD 映射。
2. 将 `fw_payload_`/`spl_` 加入现有分区顺序，其他 OTA 逻辑不变。
3. 新增从精确构建产物生成签名 A/B 包的脚本。
4. 实现根目录统一 `build.sh`。
5. 完成 PC 侧完整 AMP 构建、组件构建、host 测试和签名包验证；板端写盘
   由实机测试阶段执行。

任一 mount、write、`fsync`、回读或 unmount 失败均不推进
recovery 进度。target/current bank 仍由现有 context/recovery 层判定。
NOR payload 继续经 mailbox-backed MTD，不使用 U-Boot proper 的直接 `sf`
路径。
