## 1. 最终状态

已实现不依赖 RPMsg 的 Linux ↔ FreeRTOS 直接 IPI mailbox 双向通信：

```text
Linux /dev/starfive_ipi_mailbox
        │ 共享内存 0x6e402000 / 0x6e402400
        │ SBI AMP IPI，目标 hart4
        ▼
FreeRTOS mailbox handler
        │ 回复 Linux RX channel
        ▼
Linux read() -> 0x00011234
```

测试输入是 `0x1234`，协议会增加 `0x10000` 路由标志，因此传输值是 `0x11234`。

最终验证日志：

```text
Linux:  hart=4 type=1 ret=0
RTOS:   FreeRTOS IPI mailbox RX[0]: 0x11234
Linux:  0x00011234
```

## 2. 代码和配置位置

Linux 使用 BSP 外置模块，不编译进内核：

```text
bsp/ipi_mailbox/starfive_ipi_mailbox.c
bsp/ipi_mailbox/starfive_ipi_mailbox-test.c
bsp/ipi_mailbox/Makefile
bsp/build.sh
```

FreeRTOS 端：

```text
trusted_domain/driver/mailbox/ipi_mailbox.c
trusted_domain/app/mailbox_test.c
trusted_domain/FreeRTOS-Kernel/portable/GCC/RISC-V/port.c
```

Linux 配置保持关闭：

```text
# CONFIG_STARFIVE_IPI_MBOX is not set
# CONFIG_STARFIVE_IPI_MBOX_TEST is not set
```

DT 仍保留 IPI mailbox 节点，外置模块需要从 DT 获取共享内存和 hart：

```text
reg = <0x0 0x6e402000 0x0 0x2000>;
rtos-hart-id = <4>;
```

## 3. 通信参数

```text
RX base:       0x6e402000
TX base:       0x6e402400
共享区域大小:  8192 bytes
Linux hart:    1
FreeRTOS hart: 4
RX IPI type:   0
TX IPI type:   1
```

Linux 调用 `sbi_send_ipi_amp(hart4, 1)` 后，OpenSBI 在目标 hart 的 AMP 状态中设置 bit1，FreeRTOS 读取到 `msg_type = 0x2`。因此 Linux 侧参数是 `1`，不是 `2`。

## 日志落盘

具体参考：[日志收集方案](../方案文档/日志收集方案.md)

最终数据链路如下：

```text
SPL/OpenSBI/U-Boot UART 输出
        -> 各阶段 ramlog 保留内存
        -> Linux quard_log.ko 快照
        -> soc_logd
        -> /opt/soc_log/linux_boot_log.log

FreeRTOS EasyLogger
        -> FreeRTOS 本地 master_buf
        -> 0x6e404000 MCU 共享日志区
        -> Linux quard_log.ko 轮询并快照
        -> netlink 通知 soc_logd
        -> /opt/soc_log/mcu_log.log
```

**Linux：**

* `bsp/ipi_mailbox/consumer/quard_log.c`
* `VisionFive2_6.6/app/soc_log`

**SPL / U-Boot：**

* `u-boot/arch/riscv/cpu/jh7110/spl.c`
* `u-boot/drivers/serial/ns16550.c` 
* 通过 `CONFIG_SPL_BUILD` 选择缓冲区

**OpenSBI：**

* `opensbi/lib/utils/serial/uart8250.c`

**FreeRTOS：**

* `trusted_domain/driver/logger/src/elog_port.c`
* `trusted_domain/driver/log_backend`
