**在修改为 PMP 保护之前的板端命令如下：** 先拨码，再刷写Nor Flash，然后借助 tftp 进行主机启动
```bash
# ------ 刷写 Nor Flash ------
# 网线要插对，6.6 好像必须使用eth0
setenv ipaddr 192.168.5.9     # 板端IP

tftpboot ${loadaddr} visionfive2_fw_payload_amp.img
sf write ${loadaddr} 0x100000 ${filesize}

# 方式二：
sf probe
tftpboot 0xa0000000 u-boot-amp-spl.bin.normal.out
sf update 0xa0000000 0x0 $filesize
tftpboot 0xa0000000 visionfive2_fw_payload_amp.img

# 验证
sf read ${loadaddr} 0x0 0x40000

sf read ${loadaddr} 0x100000 0x40000

# ------ 刷写 image.fit ------
setenv ipaddr 192.168.5.9
```

## 刷写 SD 卡

**一般的固件镜像分区布局：**

| 分区 | 大小 | 文件系统 | 内容 | 谁读它 |
| :--- | :--- | :--- | :--- | :--- |
| `sdb1` | 2M | 裸数据 | U-Boot SPL（第一级引导） | JH7110 ROM（SD 启动时直接读） |
| `sdb2` | 4M | 裸数据 | `fw_payload` = OpenSBI + U-Boot（你卡上这个是普通版，不是 AMP 的） | SPL 读取并跳到它执行 |
| `sdb3` | 100M | `vfat` | boot 镜像：`starfiveu.fit`（= `image.fit`）+ `uEnv.txt` + dtbs | U-Boot 启动时加载内核 |
| `sdb4` | 2G | `ext4` | Linux 根文件系统 | Linux 挂载为 `/` |

### 启动到 initramfs
```bash
# 板上 Linux：
sudo mount /dev/sdb3 /mnt
sudo cp work/target/amp/image.fit /mnt/
sudo cp conf/jh7110_uEnv.txt conf/vf2_uEnv.txt /mnt
sync
sudo umount /mnt

mmc list  # NOR 启动下 SD 卡通常是 mmc 1（mmc 0 = eMMC）
mmc dev 1
mmc info  # 应显示容量 119.2G 的卡

# 可以直接指定，或者使用官方SDK支持的自动启动（建议）
setenv bootcmd 'ext4load mmc 1:4 ${loadaddr} /image.fit; bootm ${loadaddr}'
saveenv

reset  # 上电自动从 SD 的 ext4 分区读 image.fit 启动
```

**官方 distro boot 自动启动：**（完全自动，但要求卡上文件齐全）
VisionFive2 U-Boot 编译时就带了 distro boot（starfive-visionfive2.h 里 distro_boot_env），默认 bootcmd 会按 bootmode（拨码位）自动扫 SD/eMMC/NVMe
```bash
# 分区文件内容如下
sdb3 (vfat):  image.fit + vf2_uEnv.txt + jh7110_uEnv.txt

# 注意 vf2_uEnv.txt，要改为 image.fit 这个包名
```

### 启动到 rootfs

```bash
sudo dd if=work/target/amp/rootfs.ext4 \
    of=/dev/sdb4 bs=4M conv=fsync status=progress
```

## 内存使用

本平台的 Linux、OpenSBI、U-Boot 和 FreeRTOS 共用同一片物理 DDR，但通过
OpenSBI domain 和 Linux `reserved-memory` 划分所有权。部分地址在不同启动
阶段会被重复使用，因此“镜像曾经加载到某地址”不等于 Linux 启动后
该地址仍由原镜像占用。

### 主要物理地址

| 物理地址或范围 | 所属阶段 | 用途 |
| :--- | :--- | :--- |
| `0x40000000` | SPL / OpenSBI / Linux 运行期 | SPL 加载 AMP `fw_payload.bin` 的起点，也是 OpenSBI 入口 |
| `0x40000000-0x4005ffff` | OpenSBI 常驻 | OpenSBI 代码、可写数据、BSS 和 hart scratch；Linux 不得分配 |
| `0x40200000` | U-Boot proper，随后是 Linux | U-Boot 初始链接/入口地址；U-Boot 重定位后被 Linux Kernel 复用 |
| `0x40530000` | SPL 临时区 | `fw_payload.bin` 中附加的 FreeRTOS 临时副本 |
| `0x46000000` | U-Boot / Linux 启动 | AMP DTB 加载地址 |
| `0x46100000` | Linux 启动 | initramfs 加载地址，使用完成后释放 |
| `0x6e402000-0x6e403fff` | Linux/FreeRTOS 共享 | IPI mailbox，大小 8 KiB |
| `0x6e404000-0x6e409fff` | 共享日志 | FreeRTOS/MCU、U-Boot 和 BL1/OpenSBI 日志区，每块 8 KiB |
| `0x6e500000-0x6e6fffff` | Linux/FreeRTOS 共享 | NOR bulk-data 传输区，大小 2 MiB |
| `0x6e800000-0x6effffff` | FreeRTOS 独占 | FreeRTOS 代码、数据、BSS 和栈，共 8 MiB |
| `0x6f000000-0x6fffffff` | RTOS 预留 | OpenSBI domain 中的 16 MiB RTOS heap 区；当前 FreeRTOS 不使用该区 |
| `0x70000000` 起 | Linux | CMA 起始位置，实际大小以板端最终 DTB 和启动日志为准 |

### SPL 加载 AMP payload

SPL 把 NOR `fw_payload_a` 或 `fw_payload_b` 中的 `fw_payload.bin` 加载到
`0x40000000`。其内部布局为：

```text
0x40000000  OpenSBI 入口
0x40200000  OpenSBI payload，即 U-Boot proper
0x40530000  附加在 U-Boot 后面的 FreeRTOS 镜像
```

`0x40200000` 是相对 OpenSBI 起点的 2 MiB 对齐位置。构建时又将 U-Boot
部分填充到 `0x330000` 字节，所以 FreeRTOS 在完整 payload 内的偏移为
`0x530000`：

```text
0x40000000 + 0x530000 = 0x40530000
```

SPL 在进入 OpenSBI 前将 FreeRTOS 从 `0x40530000` 复制到最终运行地址
`0x6e800000`。复制完成后，`0x40530000` 的副本不再被 FreeRTOS 使用。

### OpenSBI 常驻区

OpenSBI 从 `0x40000000` 运行。现有 ELF 产物中，OpenSBI 自身结束于
`0x40054000` 附近；OpenSBI 传给 Linux 的保留区按边界取整为：

```text
0x40000000-0x4003ffff  代码、只读数据等，256 KiB
0x40040000-0x4005ffff  可写数据、BSS、scratch 等，128 KiB
```

Linux 启动后 OpenSBI 仍驻留在 M-mode，用于处理 SBI timer、IPI、remote
fence 和系统复位等服务。这两块内存不会返回给 Linux 页分配器。

### U-Boot 与 Linux 复用 `0x40200000`

OpenSBI 完成 domain 初始化后，将 Linux 侧启动 hart 跳转到
`0x40200000` 的 U-Boot proper。U-Boot 的初始链接范围约为：

```text
0x40200000  U-Boot _start
0x402f5b78  U-Boot 已加载段结束
0x40309a00  U-Boot BSS 结束
```

U-Boot 完成 DDR 初始化后会将自身重定位到高端 RAM。因此执行 `bootm`
时，可以把解压后的 Linux Kernel 重新放到 `0x40200000`，不会覆盖
当时正在执行的 U-Boot：

```text
启动前半段：0x40200000 = U-Boot proper 初始入口
启动后半段：0x40200000 = Linux Kernel 物理加载和执行地址
```

AMP FIT 可以先被 U-Boot 读到 `${loadaddr}`；例如已有板端日志中使用了
`0xa0000000`。该地址只是 FIT 容器的临时存放地址，`bootm` 仍按 FIT
中的 `load` 属性将各子镜像放到各自的目标位置。

### Linux Kernel、DTB 和 initramfs

AMP FIT 中三个子镜像的目标地址为：

```text
Linux Image.gz  -> 解压到 0x40200000，入口 0x40200000
AMP DTB         -> 0x46000000
initramfs       -> 0x46100000
```

现有 `vmlinux` 的链接虚拟地址为
`0xffffffff80000000-0xffffffff819d7000`。按 `0x40200000` 的物理加载起点
换算，当前内核布局约占用：

```text
0x40200000-0x41bd6fff  约 25.8 MiB
```

其中 init 段会在内核初始化完成后释放，因此该范围不等于最终不可
回收的内核大小。

DTB 文件加载到 `0x46000000`，现有文件约 46.4 KiB，板端启动日志
显示其使用区间按页取整到 `0x4600efff`。U-Boot 和 OpenSBI 在进入
Linux 前会对 DTB 执行必要的 fixup，包括：

- 按开发板实际 DDR 容量修正 memory 节点；
- 写入 initramfs 起止地址；
- 加入 OpenSBI M-mode 保留区；
- 保留 FreeRTOS、IPI mailbox、日志和 NOR 共享内存；
- 向 Linux 隐藏 hart4，并从 Linux PLIC 中排除 hart4 上下文；
- 禁止 Linux 直接使用 UART2 和 QSPI。

initramfs 从 `0x46100000` 开始。Linux 使用它完成早期用户空间初始化后，
会打印 `Freeing initrd memory` 并将对应页返回给页分配器。

### Linux 启动后的最终归属

```text
0x40000000-0x4005ffff       OpenSBI 常驻，Linux 不可分配
0x40200000-约 0x41bd7000  Linux Kernel，部分 init 内存后续释放
0x46000000 附近          Linux 启动 DTB
0x46100000 起              initramfs，初始化后释放
0x40530000 的临时副本   已无用，不再属于 FreeRTOS
0x6e800000-0x6effffff       FreeRTOS 持续运行
0x6f000000-0x6fffffff       为 RTOS 保留，当前 FreeRTOS 未使用
```

源码 DTS 中的 DDR 基准容量为 4 GiB，U-Boot 会根据开发板实际容量
修正最终 DTB。仓库最近的 8 GiB 板端日志显示，Linux 启动阶段可用
`6476756 KiB`，固定保留 `338988 KiB`，CMA 保留 `1572864 KiB`。
这些是启动阶段统计，不是进入用户空间后的实时空闲内存；实际运行状态
应通过 Linux 用户态的 `free -h`、`cat /proc/meminfo` 和 `cat /proc/iomem`
核对。

**initramfs 启用SSH和NFS**
```bash
# 永久启用 SSH
make -C buildroot O=$PWD/work/buildroot_initramfs menuconfig

Target packages
  Networking applications
    dropbear

make ampfit RTOS=freertos -j$(nproc)
```
