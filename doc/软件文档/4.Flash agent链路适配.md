# Flash 统一 PMP 保护：U-Boot 侧适配

实现 OTA A/B 分区的过程中，发现必须对 U-Boot 的 Flash 访问进行重构，
否则会影响后续 FreeRTOS 与 Linux/U-Boot 的资源隔离。

## U-Boot 侧改动概述

参考提交：[`44ca8cf7e9fdfe7a64808cf52b7f6ad50fd7075b`](https://github.com/xikao-hx/quard_star_visionfive2/commit/44ca8cf7e9fdfe7a64808cf52b7f6ad50fd7075b)

该提交的核心不是在 U-Boot 内配置 PMP，而是调整 Flash 的访问权和访问路径，
使 U-Boot proper 可以在统一 PMP 保护下继续使用 Flash：物理 QSPI 控制器交由
FreeRTOS 独占，U-Boot proper 不再直接访问 QSPI 寄存器，而是通过
`IPI mailbox -> mailbox router -> FreeRTOS NOR agent` 间接完成 Flash 读、写和擦除。
由 FreeRTOS 侧集中执行 Flash 操作和边界校验，避免 U-Boot 绕过统一保护策略。

SPL 是启动阶段的例外：FreeRTOS 启动前，SPL 仍需直接读取 QSPI 中的启动载荷；
进入 U-Boot proper 后，则禁用物理 QSPI 节点，并切换到 mailbox-backed MTD 路径。

### 改动分类

#### 1. 设备树与 QSPI 所有权切换

- `u-boot/arch/riscv/dts/starfive_jh7110-amp.dts`：保留 IPI mailbox
  `0x6E402000-0x6E403FFF` 和 NOR 数据交换区
  `0x6E500000-0x6E6FFFFF`；新增 IPI mailbox、mailbox router 和
  `nor-client` 节点，Flash 服务 ID 为 `2`；为 QSPI 节点增加
  `quard,rtos-owned` 所有权标记。
- `u-boot/board/starfive/visionfive2/starfive_visionfive2.c`：在
  `board_fix_fdt()` 中识别上述标记，将 QSPI 控制器及其子节点设为
  `disabled`。修改发生在 U-Boot proper 扫描驱动模型之前，不影响 SPL
  早期从 QSPI 启动。

#### 2. IPI mailbox 底层传输

- `u-boot/drivers/mailbox/quard_ipi_mailbox.c`：新增 U-Boot proper 侧
  IPI mailbox provider，对接两个 32 字节共享内存通道，每个通道包含
  28 字节负载和 4 字节状态。通过 SBI 扩展向 hart4 发送 IPI，
  实现 `IDLE -> DATA_READY -> ACK -> IDLE` 状态机、内存屏障、
  5 秒超时以及通知丢失时的定期重试。
- `u-boot/drivers/mailbox/Kconfig` 和 `u-boot/drivers/mailbox/Makefile`：
  新增 `QUARD_IPI_MAILBOX` 和 `QUARD_MBOX_ROUTER` 选项，且仅在
  U-Boot proper 中编译这两个驱动，不带入 SPL/TPL。

#### 3. Mailbox 消息路由层

- `u-boot/drivers/mailbox/quard_mbox_router.c`：新增路由器，从设备树获取
  TX/RX mailbox 通道，按 8 位 service ID 注册和查找 consumer，封装同步
  发送与接收接口；一个 service ID 只允许一个 consumer 占用。
- `u-boot/include/quard_mbox_router.h`：新增 consumer 消息格式、注册/解注册
  接口和收发 API，为 NOR client 屏蔽底层 IPI 通道细节。

#### 4. Mailbox-backed NOR MTD 客户端

- `u-boot/drivers/mtd/quard_nor_client.c`：新增 Flash 服务 consumer，
  通过 `NOR_GET_INFO` 获取 NOR 容量、擦除粒度和 GPT 分区信息，
  将 FreeRTOS NOR agent 公布的 Flash 注册为可读写的 `quard-nor` MTD
  master 及其分区。驱动实现 `NOR_READ`、`NOR_WRITE` 和 `NOR_ERASE`，
  大块数据通过 2 MiB 共享内存分块传输，并对读写数据做校验和
  范围/擦除对齐检查。
- `u-boot/drivers/mtd/Kconfig` 和 `u-boot/drivers/mtd/Makefile`：新增
  `QUARD_NOR_CLIENT` 选项，依赖 `DM_MTD` 和 mailbox router，仅编译到
  U-Boot proper。
- `u-boot/drivers/mtd/mtd_uboot.c`：将空字符串形式的 `mtdids`/
  `mtdparts` 视为未配置，避免空环境变量阻断 MTD 设备和分区的正常探测。

#### 5. U-Boot environment 改用 MTD

- `u-boot/env/mtd.c`：新增按名称打开 MTD 设备的 environment 后端，
  实现 `load`、`save` 和 `erase`。操作前校验 MTD 存在性、容量、
  offset 和擦除粒度；保存时执行导出、擦除和回写，加载时校验
  environment CRC。
- `u-boot/env/Kconfig`、`u-boot/env/Makefile`、`u-boot/env/env.c`、
  `u-boot/include/env_internal.h` 和 `u-boot/cmd/nvedit.c`：将
  `ENV_IS_IN_MTD`/`ENVL_MTD` 接入 environment 框架、构建系统和命令配置检查；
  新增 `ENV_MTD_NAME`，并允许 MTD backend 使用 `ENV_OFFSET`、
  `ENV_SIZE` 和 `ENV_SECT_SIZE`。

#### 6. 默认配置与用户命令

- `u-boot/configs/starfive_visionfive2_defconfig`：开启 mailbox、router、MTD、
  NOR client 和 `mtd` 命令；关闭 `ENV_IS_IN_SPI_FLASH`，改用
  `ENV_IS_IN_MTD`，将 environment 定位到 `quard-nor` 的 `0xD00000`，
  大小和擦除区均为 `0x10000`。因此 `mtd list/read/write/erase`、
  `saveenv` 和 `eraseenv` 最终都通过 FreeRTOS NOR agent 访问 Flash。

### 简要修改说明

本次 U-Boot 侧改造新增了“IPI mailbox—消息路由—NOR MTD”三层访问链路，
并将 U-Boot proper 的物理 QSPI 节点禁用。原来直连 SPI Flash 的命令和
environment 访问改由 `quard-nor` MTD 承载，最终由 FreeRTOS NOR agent
统一操作受保护的 Flash。这样既保留了 SPL 的早期启动能力，又确保
U-Boot proper 不再对 QSPI 形成第二条直访路径，为 Flash 统一 PMP 保护
提供了 U-Boot 侧适配。

## U-Boot 通过 Mailbox 访问 Flash

### U-Boot proper 禁用 QSPI 节点

AMP 启动后，SPI NOR 由 FreeRTOS 独占。U-Boot proper 不再直接访问
Cadence QSPI 控制器，而是使用以下链路访问 Flash：

```text
U-Boot mtd 命令 / environment
        -> quard_nor_client
        -> quard_mbox_router
        -> IPI mailbox
        -> FreeRTOS NOR agent
        -> FreeRTOS SPI NOR driver
```

因此，在 U-Boot proper 中看到物理 QSPI 节点为 `disabled` 是预期结果：

```text
StarFive # fdt addr ${fdtcontroladdr}
StarFive # fdt print /soc/spi@13010000 status
status = "disabled"
```

SPL 在 FreeRTOS 启动前仍可直接使用 QSPI 完成启动；U-Boot proper 启动后应使用
mailbox-backed `quard-nor` MTD，不能再用 `sf probe`、`sf read` 或 `sf update`
判断 mailbox Flash 链路是否正常。使用 `mtd list` 测试

```bash
StarFive # mtd list
List of MTD devices:
- quard-nor
  - device: nor-client
  - parent: root_driver
  - driver: quard_nor_client
  - path: /nor-client
  - type: NOR flash
  - block size: 0x1000 bytes
  - min I/O: 0x1 bytes
  - 0x000000000000-0x000001000000 : "quard-nor"
    - 0x000000000000-0x000000040000 : "spl_a"
    - 0x000000040000-0x000000080000 : "spl_b"
    - 0x000000080000-0x0000000c0000 : "gpt"
    - 0x0000000c0000-0x000000100000 : "recovery"
    - 0x000000100000-0x000000700000 : "fw_payload_a"
    - 0x000000700000-0x000000d00000 : "fw_payload_b"
```

### U-Boot CMD 改用 MTD 框架访问 Flash

`Flash` 中下载固件：

```bash
mtd list

tftpboot 0xa0000000 u-boot-amp-spl.bin.normal.out
mtd erase spl_a 0x0 0x40000
mtd write spl_a 0xa0000000 0x0 $filesize

tftpboot 0xa0000000 visionfive2_fw_payload_amp.img
mtd erase fw_payload_a 0x0 0x600000
mtd write fw_payload_a 0xa0000000 0x0 $filesize

# 然后读取回内存校验：
mtd read spl_a 0xa1000000 0x0 0x40000
mtd read fw_payload_a 0xa1100000 0x0 0x600000
```

### `saveenv` 改为接入 `MTD`，不直接访问 `Flash`

#### 适配原因

原配置使用 `CONFIG_ENV_IS_IN_SPI_FLASH`，U-Boot environment 的 load/save
最终会进入 SPI Flash backend，并调用 `spi_flash_probe_bus_cs()`、`spi_flash_read()`、
`spi_flash_erase()` 和 `spi_flash_write()`。这条路径要求 U-Boot proper 直接拥有物理 QSPI 控制器。

因此 environment 必须与 `mtd read/write/erase` 使用同一条 mailbox Flash 链路：

```text
load/saveenv/eraseenv
        -> U-Boot environment core
        -> env/mtd.c
        -> quard-nor MTD
        -> quard_nor_client
        -> quard_mbox_router
        -> IPI mailbox
        -> FreeRTOS NOR agent
        -> FreeRTOS SPI NOR driver
```

#### 配置切换

在 `starfive_visionfive2_defconfig` 中去掉 SPI Flash environment backend：

```text
# CONFIG_ENV_IS_IN_SPI_FLASH is not set
```

启用 MTD environment backend，并指定 mailbox NOR master 名称：

```text
CONFIG_ENV_IS_IN_MTD=y
CONFIG_ENV_MTD_NAME="quard-nor"
CONFIG_ENV_OFFSET=0xD00000
CONFIG_ENV_SIZE=0x10000
CONFIG_ENV_SECT_SIZE=0x10000
```

环境仍放在 NOR reserved 区起点 `0xD00000`，环境数据大小和最小擦除区域均为
`0x10000`（64 KiB）。该区域位于六个 GPT 分区之后：

```text
fw_payload_b end : 0xD00000
environment      : 0xD00000-0xD0FFFF
reserved end     : 0x1000000
```

环境区域不占用 `recovery`，也不增加第七个 GPT 分区。U-Boot 通过
`quard-nor` master 的绝对 offset 访问它，FreeRTOS NOR agent 将 canonical
reserved region 纳入 destructive range 白名单，并在实际擦写前完成最终范围检查。

#### 新增 MTD environment 后端

新增文件：

```text
u-boot/env/mtd.c
```

后端通过 `U_BOOT_ENV_LOCATION(mtd)` 注册以下操作：

```c
U_BOOT_ENV_LOCATION(mtd) = {
    .location = ENVL_MTD,
    ENV_NAME("MTD")
    .load = env_mtd_load,
    .save = ENV_SAVE_PTR(env_mtd_save),
    .erase = ENV_ERASE_PTR(env_mtd_erase),
    .init = env_mtd_init,
};
```

`env_mtd_open()` 是三个操作的公共入口：

1. 调用 `mtd_probe_devices()`，确保 mailbox NOR client 已完成 probe；
2. 使用 `get_mtd_device_nm(CONFIG_ENV_MTD_NAME)` 获取 `quard-nor`；
3. 校验 MTD erase size、环境 offset 对齐、64 KiB 擦除区对齐和 master 边界；
4. 任一条件失败时返回错误，不回退到 SPI Flash backend。

对应代码：

```text
u-boot/env/mtd.c
```

#### `load` 流程

U-Boot proper 加载环境时执行：

```text
env_mtd_load()
    -> env_mtd_open("quard-nor")
    -> mtd_read(quard-nor, 0xD00000, 0x10000)
    -> mailbox NOR_READ
    -> env_import(..., check=1)
```

`env_import(..., 1, ...)` 会检查 environment CRC。读取失败、MTD 尚不可用或 CRC
无效时使用默认环境，但不会尝试访问物理 QSPI。

#### `saveenv` 流程

执行 `saveenv` 时：

```text
env_mtd_save()
    -> env_export() 生成包含 CRC 的 64 KiB environment
    -> env_mtd_open("quard-nor")
    -> mtd_erase(quard-nor, 0xD00000, 0x10000)
    -> mailbox NOR_ERASE
    -> mtd_write(quard-nor, 0xD00000, 0x10000)
    -> mailbox NOR_WRITE
```

当前 `CONFIG_ENV_SIZE` 与 `CONFIG_ENV_SECT_SIZE` 相等，保存时只擦写这一整个
64 KiB 区域，不会触碰 `recovery@0x0C0000` 或任何 payload 分区。MTD write/erase
请求仍须通过 FreeRTOS 侧 reserved range、对齐和 NOR master 边界校验。

#### `eraseenv` 流程

启用 `CONFIG_CMD_ERASEENV` 后，执行 `eraseenv` 会进入：

```text
env_mtd_erase()
    -> env_mtd_open("quard-nor")
    -> mtd_erase(quard-nor, 0xD00000, 0x10000)
    -> mailbox NOR_ERASE
```

擦除后下次启动会因环境内容为空而使用默认环境。`eraseenv` 是破坏性操作，仅在明确
需要清除持久化环境时使用。

#### Kconfig、Makefile 和 environment core 接入

除新增 `env/mtd.c` 外，还需要完成以下接入：

- `u-boot/env/Kconfig`：新增 `ENV_IS_IN_MTD` 和 `ENV_MTD_NAME`，并允许
  `ENV_OFFSET`、`ENV_SIZE`、`ENV_SECT_SIZE` 用于 MTD backend；
- `u-boot/env/Makefile`：仅在 `CONFIG_ENV_IS_IN_MTD=y` 时编译 `mtd.o`，并放在
  `ifndef CONFIG_SPL_BUILD` 内，避免将 U-Boot-proper-only backend 编进 SPL；
- `u-boot/include/env_internal.h`、`u-boot/env/env.c`：增加 `ENVL_MTD` location，
  使 environment core 能查找到 MTD driver；
- `u-boot/cmd/nvedit.c`：将 `CONFIG_ENV_IS_IN_MTD` 加入合法 environment device
  backend 列表，否则会在编译阶段报“Define one of CONFIG_ENV_IS_IN_...”错误；
- `u-boot/configs/starfive_visionfive2_defconfig`：关闭 SPI Flash environment，启用
  MTD environment，并固定 `quard-nor`、offset、size 和 erase region。

SPL 仍需在 FreeRTOS 启动前通过物理 QSPI 读取启动 payload，但 SPL 不加载、保存或
擦除这个 MTD environment。MTD backend 只服务于 U-Boot proper。

#### 板端验证

先确认 `quard-nor` 已注册：

```text
mtd list
```

然后保存环境：

```bash
setenv ipaddr 192.168.5.9
setenv serverip 192.168.5.11
saveenv
printenv ipaddr serverip
reset
```

重启后再次检查：

```text
printenv ipaddr serverip
```

预期两个变量保持为保存值，启动和保存过程中不再出现 `SPIFlash`、`Invalid bus 0`
或 `spi_flash_probe_bus_cs()` 错误。FreeRTOS 侧应看到 environment 区域对应的
`NOR_ERASE` 和 `NOR_WRITE` 请求。

如需验证清除环境，先记录必要的网络参数，再执行：

```text
eraseenv
reset
printenv ipaddr serverip
```

预期重启后恢复默认环境。该步骤会清除已保存的 U-Boot 环境，不应作为普通
`saveenv` 验证的必选步骤。

### 优化 FreeRTOS 侧 Flash 驱动

具体参考： [FreeRTOS SPI NOR驱动移植方案](../方案文档/FreeRTOS%20SPI%20NOR驱动移植方案.md)

本方案的核心目标是：

- 将 4 KiB 写入从 512 次 8 Bytes Page Program 降为 16 次 256 Bytes Page Program。
- 将大块读取从重复 8 Bytes STIG 命令改为 Cadence indirect read。
- 保留当前 `spi_nor_*()` 对外 API、FreeRTOS mutex 和 NOR agent 协议。
- 不引入 U-Boot driver model、`spi-mem`、MTD、设备树解析和动态内存依赖。
- 物理 QSPI 仍只归 hart4 FreeRTOS 所有，Linux 和 U-Boot proper 继续通过 mailbox NOR agent 访问。
